### 🧠 Problem-Solving Patterns

The following patterns are currently implemented or under active focus:

#### 🟢 Arrays & Hashing
* **Prefix Sum & Subarrays**: Subarray optimization techniques (e.g., maximum absolute subarray sum).
* **Frequency Maps**: Using hash maps/sets for linear-time frequency analysis.
* **Matrix & Simulation**: Iterating, modifying, and verifying structures in-place.

#### 🟢 Math & Bit Manipulation
* **Bitwise Operations**: Bit flip counting, bit weight computation, and masks.
* **Math Sequences**: Memoized and recursive progressions (Fibonacci, Tribonacci).
* **Number Theory**: Prime sum computation and reversing operations.

#### 🟡 Two Pointers & Sliding Window
* **In-place Mutation**: Modifying arrays/strings with write-pointers (String compression).
* **Variable Windows**: Tracking contiguous segments with count/frequency constraints.

#### ⏳ Topics I'm working toward
* **Linked Lists**: Reversals, slow & fast pointer cycles, and node merging.
* **Trees & Graphs**: Breadth-First Search (BFS), Depth-First Search (DFS), and backtracking.
* **Advanced DP**: Knapsack, interval DP, and multi-state decision paths.

### ⚡ Complexity Reference

Every solution is written with optimal space and time complexities in mind.

| Complexity | Class | Description |
| :--- | :--- | :--- |
| **O(1)** | Constant | Execution time remains same regardless of input size. |
| **O(log n)** | Logarithmic | Input size is halved at each step (e.g., Binary Search). |
| **O(n)** | Linear | Execution time grows proportionally to input size. |
| **O(n log n)** | Linearithmic | Standard sorting performance (e.g., Merge Sort). |
| **O(n²)** | Quadratic | Typical of nested loops over the input. |
